# Ubuntu 7.3补丁去重与X1E电源改进核对（2026-09-19）

后续实机发现了QRTR握手导致的Wi-Fi恢复回归，已增加按源码状态携带的0006回退补丁。
它不改变下文五组硬件补丁的审阅结论；故障对照、成功实验和未来去重策略见[单独记录](7.3-wifi-resume.zh-CN.md)。

## 实际基线

Ubuntu源包为`linux 7.3.0-5.5`，源码Makefile的`EXTRAVERSION=-rc3`，对应上游[v7.3-rc3](https://github.com/torvalds/linux/tree/fd73f4a6659897191fa0d40695fe370925dd3780)。这里不是把Ubuntu包名当成上游7.3正式版。对照基线为Ubuntu`7.2.0-5.5`和上游[v7.2](https://github.com/torvalds/linux/tree/8d3ae59288f1e7d58d76558a6ee96d533bc5019f)。

核对方法：直接比较两个上游tag的Git树和文件内容，再比较Ubuntu源包中的对应文件。不能只按提交日期筛选：较早写成、稍后合并的补丁会被日期筛选漏掉。此次CPU、SCMI、PSCI、CPUCP、GENI SPI、GPI、ath12k及Romulus/Hamoa设备树等13个关键文件，在两个Ubuntu基线中分别与对应上游tag逐字节相同。未声称整个Ubuntu内核没有发行版补丁。

## 本地五组补丁

| 组 | 7.3-rc3状态 | 处理 |
|---|---|---|
| 0001 Wi-Fi rfkill | ath12k仍没有本机WCN7850/Romulus13例外 | 保留；严格应用成功 |
| 0002 QSPI/GPI/SPI HID | 本机QSPI兼容项、GPI扩展和这套通用SPI HID transport仍未合入；GENI资源/PM框架已有较大重构 | 保留硬件功能，使用7.3专用变体移植controller部分；其余GPI/HID/DT差异保持原补丁 |
| 0003 GTCH SPI触屏DT | Romulus13仍无本机GTCH SPI节点；不是早期I2C触屏提案 | 保留 |
| 0004 SPI HID供电/睡眠 | 本地transport文件在上游不存在，因此对应生命周期修复也未被上游同一驱动替代 | 保留 |
| 0005 GPIO所有权/panel供电 | 本地触摸节点及panel关联仍需提供 | 保留 |

没有发现可整组删除的已合入补丁。也不能只看补丁文件名或应用失败就认定已合入。7.3变体保留上游的`geni_spi_desc`资源/时钟/供电回调、SA8255P匹配项和scoped runtime-PM保护；把本地QSPI开关合入该描述结构，移除旧的独立match-data结构和手动PM清理跳转，避免覆盖或重复上游实现。

相关上游变化：[资源初始化](https://github.com/torvalds/linux/commit/647277240b3623808c583d3d38e74d47180f60de)、[runtime PM helper](https://github.com/torvalds/linux/commit/059e41aab4c860287bbef20c8ea11cff5731883d)、[PM错误检查](https://github.com/torvalds/linux/commit/d8e9ea989acb54508477e4a8c9d9eaf8217e0081)、[无效协议返回值修复](https://github.com/torvalds/linux/commit/2c1c13da3a3a639d2ac7221e1a5e57945cbc7235)。

`patches/series`仍定义五组及顺序；`patches/variants/7.3/`仅替换0002。7.2继续使用原补丁，7.3按源码版本选择变体。两组均已在原始Ubuntu文件上以`--fuzz=0`重放成功，7.2 SPI结果与原实现一致。7.3 Romulus13设备树已独立编译通过，确认同时包含触控板、触摸屏和domain_ss3；16项本地回归测试通过。完整内核编译与实机验收是后续独立检查。变体参与构建缓存指纹，BUILD.json记录实际选择的路径及哈希。之后的新系列仍会严格尝试补丁，失败就通知，不自动跳过。

Ubuntu ABI不带上游`-rcN`后缀，因此构建显式传递`EXTRAVERSION=`，同时把原始后缀记入BUILD.json；不修改源包Makefile，不把RC代码误标为已通过正式版实机验证。

## 对X1E有意义的新增改进

1. **更深的CPU子系统空闲状态domain_ss3。** Hamoa设备树新增系统级idle状态，进入/退出各2500us，最短驻留9000us；同时将cluster_cl5的进入/退出延迟调整为各2000us。上游说明其为更深的芯片电源轨掉电提供条件，依赖PDC正确处理GPIO唤醒。它与手动offline若干核心不同。[上游提交](https://github.com/torvalds/linux/commit/95f827ceb21e2885f40eec5d93a340abbcc22d13)
2. **CPUCP mailbox可靠性。** 添加空消息处理，避免SCMI清通道通知导致空指针访问；调整IRQ回调锁定范围，修复PREEMPT_RT下的自锁。当前Ubuntu配置不是PREEMPT_RT，不能把后一项直接解释成当前机器会节省若干瓦。[空消息修复](https://github.com/torvalds/linux/commit/fc4f2f99530298a1739226947aa76525142d421d)、[RT锁修复](https://github.com/torvalds/linux/commit/3690aaa6d18f6775c3e7932fb8af8c5bf6a6b69c)
3. **SCMI生命周期修复。** 涉及设备引用、协议注册失败回滚、设备移除竞态、通知停止及通道清理；属于固件通信稳定性修复，不是新的CPU governor。[设备移除竞态](https://github.com/torvalds/linux/commit/2c4097e6c4aed276c5e9ec2ab331ab397ea780bf)、[清理前停止通知](https://github.com/torvalds/linux/commit/8e49055d0d495c9c07575ad8e111d9eaf0efb13f)
4. **PSCI CPUIdle延迟探测恢复。** 从不支持所需probe deferral的faux device回到platform device注册，改善依赖设备未就绪时的初始化。[上游提交](https://github.com/torvalds/linux/commit/0606f2114e2dc88fe293858fd991cda2688b8c3a)

SCMI CPUFreq驱动本体在这两个基线中逐字节相同。本机已有的`scmi_cpufreq`加载配置仍有价值，不能认为升级到7.3就自动获得新的调频算法或Windows式核心停放。现有调频驱动生效带来的功耗下降，与7.3新增系统idle状态是两件事。

还有平台改进：Romulus USB PHY的电源轨映射修正、Hamoa USB时钟/interconnect配置修正。它们不等同于完整Qualcomm USB4主机链路支持，更不能据此宣称Surface TB4 Dock已可用。

以上为已合入源码的核对结果。新深度idle是否实际进入、是否影响唤醒和触摸设备、整机功耗能降低多少，仍需独立签名新内核的实机验收。保留现有Secure Boot、可用内核和启动参数，不在此轮修改本机功耗对照设置或自动重启。
