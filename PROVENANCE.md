# Patch provenance

Baseline reviewed on Ubuntu source `linux 7.2.0-5.5`, Microsoft Surface Laptop 7 15-inch X1E / Romulus15 (SMBIOS SKU `Surface_Laptop_7th_Edition_2037`). Records before 2026-09-25 called this machine the 13.8-inch Romulus13 because it had booted the Romulus13 DTB; the hardware and all test results are unchanged. Subsequent Ubuntu versions require successful patch application, builds, and separate hardware qualification.

- `0001`: Local port of the ath12k rfkill workaround, limited to Romulus15, based on [bryce-hoehn/linux-surface-laptop-7](https://github.com/bryce-hoehn/linux-surface-laptop-7).
- `0002`: QSPI/GPI and SPI HID transport from [ProgrammerIn-wonderland/ELLX-Kernel](https://github.com/ProgrammerIn-wonderland/ELLX-Kernel), commit `0e9944fa4cf2ccf575f5162bfd53ed4dc1592251`, ported to Ubuntu with lifecycle fixes and Romulus15-only wiring. It targets Ubuntu `7.3.0-5.5` / upstream `v7.3-rc3`, retaining the upstream GENI resource callbacks, scoped runtime-PM acquisition and SA8255P support; see [the upstream audit](docs/7.3-upstream-audit.zh-CN.md). The original Ubuntu 7.2 version, which differed only in the SPI-controller portion, was retired on 2026-09-27 together with 7.2 support.
- `0003`: GTCH SPI touchscreen wiring derived from this model's Windows ACPI and the SPI transport investigation. It replaces the unsuccessful I2C touchscreen experiment; it is not the LKML I2C proposal.
- `0004`, `0005`: Local 2026-09-15 SPI HID power-lifecycle, GPIO ownership and DRM panel follower changes. These extend the first three patches and must be applied as a set.
- `0007`–`0012` (2026-09-27): Local SPI HID transport fixes on top of `0002`/`0004`, derived from static analysis of this machine's Windows `hidspi.sys` / `HidSpiCx.sys` (Microsoft public symbols) and `qcspi8380.sys`: bounded input reports and fragment reassembly, device-initiated reset recovery with a runtime `reset_recovery` switch, feature responses read under the lock, 4-byte output padding, power cycling of unresponsive devices, and supply error propagation. They touch only `drivers/hid/spi-hid/` and are not yet hardware-validated; see [the validation checklist](docs/spi-hid-windows-parity.zh-CN.md). No Windows code or disassembly is included.
- `0013`–`0017` (2026-09-27): Follow-ups to `0007`–`0012` from the same Windows analysis and the decoded `BSRC_QSPI*.bin` resources: removal of enumeration work left unused by `0008` (moving the HIDSPI version check into enumeration), report IDs passed only when the device sends one, re-reading while an edge-triggered interrupt stays asserted (with `irq-gpios` on the touchscreen), a probe-time log of `GENI_IF_DISABLE_RO` on QSPI controllers, and Windows' QSPI pin pull-downs and touchscreen drive strength. Checked against Ubuntu 7.3 only; not yet hardware-validated; see [the validation checklist](docs/spi-hid-windows-parity.zh-CN.md).
- `0018`, `0019` (2026-09-27): DisplayPort audio links for both USB-C ports, and the Iris video codec with Microsoft-signed `qcvss8380.mbn` taken from Windows, on Romulus15. Both follow the Surface Pro 11 device-tree patches for the same SoC ([dwhinham/linux-sp11](https://github.com/dwhinham/linux-sp11)). The firmware is not redistributed. Not yet hardware-validated; see [the checklist](docs/romulus15-dp-audio-iris.zh-CN.md).
- `0020` (2026-10-23): Enables Surface Aggregator POS (posture) events on the Surface Laptop 7 by adding the existing POS tablet-switch node to its node group, and teaches the tablet-switch driver the lid posture source (ID 1: 2 = closed, 3 = laptop, never tablet mode). It fixes a touchpad that stays silent with no haptics after a lid close the host did not see (reproduced by closing the lid right after starting a Windows shutdown); the EC releases the touchpad only once a host has enabled POS events and taken the pending posture change. The request bytes match those Windows' SurfaceHotPlug sends at boot, found by static analysis of this machine's driver. Hardware-validated on Romulus15 / SAM 26.4.139 with locally signed modules: the stuck touchpad recovered at runtime when the events were enabled and recovered by itself on a boot after reproducing the fault, with tablet mode staying off. No Windows code or disassembly is included.
- `0021` (2026-10-23): Local SPI HID fix found while comparing against the upstream spi-hid v5 series and Jizhou Tong's Romulus13 QSPI RFC: after 100 consecutive header or read errors the IRQ thread masked its line, `spi_hid_stop()` disabled it again and `spi_hid_start()` enabled it only once, leaving the touchpad or touchscreen silent until reboot. The stop path now drops the thread's disable and start clears the error count. Compile-tested only; not yet hardware-validated.
- `0022` (2026-10-23): Front OV02C10 camera on Romulus15, in a separate `x1e80100-microsoft-romulus15-camera.dtsi`: PM8010 camera supplies, CCI1, CSIPHY4, the sensor on CCI1 bus 1 at 0x36 with MCLK4 and a GPIO237 reset, CAMSS port 3, and the existing GPIO225 indicator as the privacy LED. The node shape is Oliver White's Romulus camera series on [linux-arm-msm](https://patchwork.kernel.org/project/linux-arm-msm/patch/20260409201717.108169-3-oliverjwhite07@gmail.com/) (changes requested; carried by [ELLX](https://github.com/ProgrammerIn-wonderland/ELLX-Kernel) commit `36afa550628cf584a7e4a1d1c894fa36515c808d`). The regulators use flat voltages, as Konrad Dybcio asked in review. This machine's ACPI (`\_SB.CAMF`, `OVTI02C1` / `MSHW0470`) and Windows' `CAMF_RES_MSHW0470.bin` / `SCFG_FRONT_MSHW0470.bin` confirm the sensor, the I2C address, the LDO1/3/5 rails and the reset GPIO. The MCLK pin, the CCI bus and the CSIPHY lanes come from the reference shape. Also backports Felipe Calliari's [`media: ov02c10: Implement get_selection`](https://patchwork.kernel.org/project/linux-media/patch/20260923234100.318151-3-calliarifelipe@gmail.com/) (v3, Reviewed-by Bryan O'Donoghue, not yet merged) to the 7.3 pad-op signature, in place of ELLX's driver change. Not yet hardware-validated. No Windows files are redistributed.
- `0023`–`0025` (2026-10-23): Upstream Parade PS883x retimer dock-compatibility series by Jens Glathe, cherry-picked unchanged (original authorship, Acked-by/Tested-by and Signed-off-by trailers retained) from gregkh/usb.git `usb-next` commits [`42411ff1a7bb`](https://git.kernel.org/pub/scm/linux/kernel/git/gregkh/usb.git/commit/?id=42411ff1a7bbd1da609cdc18c0f2c43cd39d2b31) (accept legacy DP pin assignment F), [`d9eadbba6663`](https://git.kernel.org/pub/scm/linux/kernel/git/gregkh/usb.git/commit/?id=d9eadbba6663a5361699310959422a85e128e416) (30 ms settle delay after configuration writes) and [`647f31f34d40`](https://git.kernel.org/pub/scm/linux/kernel/git/gregkh/usb.git/commit/?id=647f31f34d4010fa565de284ef4a5bbd099f6575) (reject USB4 on X1E/X1P so docks fall back to USB3 + DP Alt Mode); [v5 series](https://patchwork.kernel.org/series/1171308/). They are in the `usb-7.4-rc1` pull request and are expected in v7.4-rc1; only the hunk line numbers were regenerated against Ubuntu `7.3.0-9.9`, whose `ps883x.c` lacks the upstream probe-time accessibility read. Listed in `series-if-needed` so a kernel that already carries them is recognized and skipped. Compile-tested only; not yet hardware-validated on Romulus15.
- `0026`, `0027` (2026-10-23): Bartosz Golaszewski's ["crypto: qce - make algos optional and remove the BROKEN label" v11](https://patchwork.kernel.org/series/1191131/) (2026-10-22, Cc stable, Reviewed-by Konrad Dybcio, tested on an X1E80100 Yoga Slim 7x), unchanged. The QCE driver binds to the enabled `crypto@1dfa000` node only to gate its clocks and drop its interconnect vote; it registers no crypto algorithms unless `qcrypto.do_register_algos=1`, so the CPU's ARMv8 Crypto Extensions stay in use. Without a bound driver both `qnoc-x1e80100` interconnect providers never reach `sync_state()` and keep every vote at maximum. `ci/build.py` builds `CONFIG_CRYPTO_DEV_QCE=m`. The GPU's GMU still blocks GCC/GPUCC `sync_state()` until Akhil P Oommen's "drm/msm: Attach a driver to GMU" lands; meanwhile `fw_devlink.sync_state=timeout` on the command line covers it. Forcing these `sync_state()` calls at runtime on Romulus15 lowered idle power by about 0.6–0.8 W. Compile-tested; the QCE probe itself is not yet hardware-validated.
- `0006` (retired 2026-09-27; Ubuntu `7.3.0-6.6` / v7.3-rc4 carries the upstream fix [net: qrtr: resend HELLO on MHI resume](https://ratatoskr.run/lkml/2026/07/17348346/t)): Local revert of upstream [544d85de4dc2](https://github.com/torvalds/linux/commit/544d85de4dc22c01badfd8cefa59829ce35c4858), restoring QRTR HELLO handling after firmware restarts with a retained MHI endpoint. One deep-resume hardware test passed on Ubuntu `7.3.0-5.5` with the original PCIe policy. The reviewed optional series recognizes unaffected source without modifying it; unknown changes fail. See [the regression and validation record](docs/7.3-wifi-resume.zh-CN.md).

The original three-patch maintenance archive is [ItsLucas/surface-laptop-7-linux-maintenance](https://github.com/ItsLucas/surface-laptop-7-linux-maintenance). Existing patch headers and authorship are retained; no contributor sign-offs are fabricated. Kernel and device-tree changes retain the licenses of their respective upstream files. New CI scripts and tests are provided under GPL-2.0-only.

Ubuntu source, buildinfo versions and download URLs, the exact recipe commit, all patch hashes, public-certificate fingerprint, toolchain inventory and source package checksums are included in each `BUILD.json`. Reproduce using the repository at that commit and the recorded Ubuntu packages. No proprietary firmware is distributed by this pipeline.

## PLD hwmon modules

The original GPL-2.0-only implementation in `drivers/qcom-pld-power/` was developed
from locally observed Windows EMI metadata, static interface analysis of the
installed Qualcomm PEP driver, and Linux read-only/affinity/suspend experiments.
It is built as two external modules against each candidate kernel's generated
ABI; it is not a copied Windows driver or an upstream-merged kernel patch.

The protocol/resource evidence, driver hash, units, test scope and unresolved
questions are recorded in [`PROTOCOL.md`](drivers/qcom-pld-power/PROTOCOL.md) and
[`pld-power-validation.md`](docs/pld-power-validation.md). No proprietary binaries,
disassembly, raw device captures, private keys or firmware images are distributed.
